## 1. Goal

两层交付，Phase 5 链路首次获得落盘面并收口：

1. **纯函数层**：`build_review_queue_request(eligibility, reflection, enriched)` —— 仅 eligible 时产出不可变 queue request artifact（dict）与 `rq_` identity；对 ineligible 输入 fail-closed 报错。
2. **持久化层**：`state_dir` 下 `E → R → El → (仅 eligible) Q` 全链的类型化 preflight（零写入 + 限定 temp 清理）、no-replace 原子发布序列、崩溃重放收敛；关闭 E5。

⚙ 计划级决定（r2 修订后，供红队复审）：
- ⚙-1 canonicalizer 模块内复制（同 S5.3 先例），不引入公共 API；**独立 oracle**：S5.4 测试段以硬编码 golden 字节字面锁定（含非 ASCII task_id 的 `\uXXXX` 双层转义、内嵌双引号 run_id、附录 C 浮点边界向量），不得用同一序列化器自证（r1-13）。
- ⚙-2 纯函数与 I/O 分两文件：`queue_request.py` 沿用 no-I/O subprocess audit 全套；`persistence.py` 全部 fs 操作经**单一受审 I/O shim**。**shim 完整最小接口（r6-M2 冻结，r7-M1 增补）**：`lstat`、`scandir_names`、`read_bytes`、`open_exclusive`（O_CREAT|O_EXCL）、`write_all`（短写循环补齐或失败）、`close`、`fsync_file`、`fsync_dir`、`mkdir`、`link`、`unlink`、**`resolve_path`**（必要时 `pathconf`）。路径字符串计算不属 fs 操作，但任何触发磁盘查询的调用（`Path.exists()`/`is_file()`/`resolve()` 等）**不得在 shim 外发生**。**两层权限边界（r7-M1，消除 RED-2/RED-9 互斥）**：
  - **路径 Gate 只读允许面**：`lstat`/`resolve_path`/`pathconf` 可**只读**访问 state_dir 及其祖先组件、`known_sync_roots()`、`~/Library/CloudStorage`、`forbidden_roots`、仓库根判定所需的明确候选路径——真实路径禁区判定必需，仅此阶段、仅此列表。仓库根以**纯词法方式**从 `__file__` 固定包布局推导（不扫描父目录 `.git`）。
  - **持久化允许面**：一切变更操作（create/write/link/unlink/mkdir/fsync_dir）**无条件**限于 state_dir 子树；路径 Gate 完成后，artifact 读取与发布同样只触 state_dir 子树；A4 queue 枚举例外不变。
- ⚙-3 temp nonce 来源 `os.urandom` hex（基线明示 nonce 仅入文件名不入内容；r1-14 确认合规）。
- ⚙-4 **两个入口，共用同一 preflight 与发布路径**（r1-1/3/7、r2-B1/B2 修订）：
  - `persist_learning_chain(state_dir, enriched, *, forbidden_roots=())`：首写与重试（同对象）。内部：冻结 build_reflection → 冻结 build_eligibility → **按自产 `eligibility_status` 分支**（§7 注：读取自产 status 决定是否写 Q 属 §5 冻结职责，不在禁令内）——eligible 走 E→R→El→Q；ineligible 走 E→R→El 终止。
  - `resume_learning_chain(state_dir, evaluation_id, source_snapshot_digest, *, forbidden_roots=())`：**state 根寻址恢复，前置条件 = E 已持久在盘**。两个入参先过 ID 语法正则（§4.2，用作路径段前强制）→ 从磁盘读 E → E canonical 字节自检（§3.5）→ §4.2.1 全套再准入 + digest 复算 == 目录段 + **路径绑定等式**（`E.source_evaluation_id == E.source_evaluation_snapshot.evaluation_id == 所在 evaluations/{} 段`，r2-B2；字段名依契约 06 冻结 schema，r3ext-D1）→ 重放冻结 producer 链 → 从缺失的第一环补完。E 缺失而下游存在 = 非前缀 → 报错（E 为根证据不可补写）。
  - **恢复责任划分（r2-B1、r3ext-A1 修订）**：路由判据是**重启后观察到的磁盘状态**，不是崩溃发生的执行点——E target 存在（且通过 §3.5 E 字节级检查）→ `resume_learning_chain` 收敛；E target 不存在（含 ∅、∅+temp，preflight 清 temp 后即合法 ∅ 态 =「链未持久开始」）→ 调用方持 enriched 重新 `persist_learning_chain`；resume 对无 E 状态 fail-closed 报「E 不存在」。E 的 link ③ 与目录 fsync ⑤ 之间崩溃的两种物理结局（目录项存留 / 丢失）分别落入上述两支，无未路由状态；**持久化补全规则（r4-B1 推广至全链，r5-1 扩展至目录）**：恢复/重试路径上——① 对**发布路径上的每一级目录**，无论本次新建还是已存在，一律（重新）执行 `fsync(父目录)`，自根向叶（幂等；崩溃后无法区分该目录项是否已持久，补发消除"空 digest 目录项未持久、后续 Q 幸存而 E/R/El 目录项丢失"的非前缀风险）；② 对**每个**已存在且通过字节校验的 target（E/R/El/Q 一律），在继续下游发布前补发一次幂等 `fsync(所在目录)`——补发使 ⑤ 的持久化保证在任何幸存结局下重新建立；El 目录的补 fsync 先于任何 Q 发布类操作（维持 §3.6 链级顺序），Q 幸存时补 `fsync(review_queue)` 后链即完整。fsync 非命名空间/内容变更，不在 §3.5 preflight 写豁免清单管辖内，其执行位置恒在只读 preflight 判定合法之后（r5 Part B-3 确认口径，此处显式化）。两入口对每一可达磁盘状态的裁决构成**收敛矩阵**（RED-6 逐点锁定，E/R/El/Q 各自 ③–⑤ 窗口两种结局都注入），无二义。
  - ineligible 链的 corruption 检查（`ineligible ∧ Q 存在`）：预期 Q 路径由 `rq_ = "rq_"+sha256(canonical({"source_eligibility_id": ...}))` **纯哈希直接计算**，不调用会拒绝 ineligible 的 producer（r1-1）。
- ⚙-5a **state_dir 存在性契约（r6-M1 冻结）**：两个公开入口均要求 `state_dir` 已存在且为非 symlink 真实目录；**入口不得创建 state_dir 根目录**（不存在/类型不符 → fail-closed 报 path gate）。S5.4 的目录创建权限自 `evaluations/` 与 `review_queue/` 子目录开始——根目录写入永不发生于 typed preflight 与 probe 之前，崩溃矩阵无需扩展根目录态。
- ⚙-5 fs 前置条件自实现（r1-4、r2-C2 修订，不复用 `check_state_dir`）：拒绝集 = `known_sync_roots()` ∪ `~/Library/CloudStorage`（macOS File Provider 根）∪ state_dir 位于仓库/数据根内的既有规则；能力 probe 冻结序列（r7-m1 闭合双名称清理）：`open/write/fsync/close → link(source, target) → unlink(target) → unlink(source) → fsync_dir(state_dir)`，任一步失败 → 启动即 fail-closed；**成功返回时断言两个 probe 名称均不存在**（失败/崩溃残留由下次 preflight 清理）。**probe 保留命名空间**：探针源 `.tmp.probe.<nonce>`、link 目标 `.tmp.probe-target.<nonce>`，均在 state_dir 根且均以 `.tmp.` 前缀落入既有清理域——probe 任意点崩溃的残留物即 `.tmp.*` 残留，不进合法前缀模型，无新崩溃类别。**路径健全性**（r3ext-D3、r4-C1，继承 `check_state_dir` 既有边界并扩展至子路径）：state_dir 为 symlink → 拒绝；全部包含性判定（同步根/仓库/数据根）在 `resolve()` 解析后的真实路径上执行，文本路径经 symlink 逃入禁区必被检出；**子路径无 symlink 不变量**（r5-4 界定豁免）：preflight 与发布触碰的每一条 state_dir 子树路径的**目录组件**（evaluations/ 逐级、digest 目录、review_queue/）及**正式 target 与自产 temp 叶**逐组件 `lstat` 校验非 symlink（或等价断言 `resolve()==字面拼接`），任一组件为 symlink → fail-closed——保证 ⚙-2 "只触 state_dir 子树"承诺在物理路径层成立。**唯一豁免：待清理的匹配 `.tmp.*` 叶节点**——POSIX `unlink` 不解引用最终组件（symlink 叶被 unlink 只删除链接本身，已实测验证），temp 从不被 open/read，故对匹配名不做 lstat 即直接 unlink 既满足 A4 名称使用约束，又无越界 I/O 风险；其父路径（字面计算所得，非匹配名）仍受组件校验。**保证强度界定（r6-M5 收窄）**：本条与全部路径物理约束建立在**单写者且执行期间无外部目录树变更**的前置条件上（⚙-6 同源）；入口检测调用开始时及每个已定义操作点**可见的** symlink 或类型异常，**不承诺抵抗恶意并发目录替换**（TOCTOU 完整防御需 dirfd/openat/O_NOFOLLOW 架构，超出本 sliver 最小代码边界，明示为非目标）。**禁区来源**（r4-C2）：拒绝集 = known_sync_roots() ∪ CloudStorage ∪ 自探测仓库根（`_repository_root` 同型自导出，无需调用方输入）∪ **调用方显式传入的 `forbidden_roots=()`**（数据根等调用方权威边界经此参数供给，⚙-4 两入口签名同步增加该 keyword 参数；不传则该类不检查——权威在调用方，与 G-5 同性质）。**执行顺序**（r3ext-D2）：① 只读路径健全性与同步根检查 → ② 只读类型化链 preflight（§3.5，含 corruption 检测）→ ③ 能力 probe（保留命名空间内的变更）→ ④ 发布；链状态非法时 probe 永不执行，零写入拒绝语义不被 probe 破坏（temp 清理豁免仍限 §3.5 白名单）。
- ⚙-6 **单写者前置条件**（r1-5 修订）：一个 state_dir 同时至多一个写者，由调用方保证——与 §9 隔离前置条件（G-5）同性质的接口契约，文档化于模块 docstring 与错误消息。link create-if-absent 仲裁降为纵深防御：序列中任何异常（含 temp 被外部移除的 ENOENT）→ fail-closed 报错，不静默重试；随后 resume 收敛。不引入锁文件。
- ⚙-7 首写、重试、崩溃恢复共用同一 preflight 路径，无特殊分支（r1-3 下的重申：分叉仅在入口如何获得 enriched——内存态 vs 磁盘 E 再准入）。
- ⚙-9 **入口返回值与异常契约（r6-M3 冻结）**：两个入口在首次写入、幂等重放、恢复完成三种结局下返回**同一结构** `{"eligibility": <eligibility artifact>, "review_queue_request": <rq artifact | None（ineligible）>}`，返回值 alias-free（深改不影响内部状态）。异常统一为单类 `class PersistenceError(ValueError)`，携带 `gate` 与 `code` 两个字段；gate 冻结五类：`path`（路径/存在性/symlink/禁区）、`preflight`（非前缀/corruption/字节不等）、`capability`（probe 失败）、`publish`（发布序列异常）、`readback`（temp 读回不符）。调用方可依赖 gate 稳定分类；不建异常层级。**producer 异常包装（r7-m3）**：入口调用 producer 或执行再准入时出现的任何输入/schema/equation/canonicalization 错误（`ReflectionInputError`、`EligibilityInputError`、queue producer 输入错误等），统一包装为 `PersistenceError(gate="preflight", code="invalid_input")`，不向调用方泄漏 producer 专属异常类型。
- ⚙-10 **持久化层 canonicalizer 唯一权威（r6-M4 冻结）**：`persistence.py` 自含一个私有附录 C canonicalizer，**唯一负责全部四类落盘 artifact（E/R/El/Q）的字节生成与字节比较**；不得调用 reflection_builder/eligibility/queue_request 各模块的 serializer 决定磁盘字节（producer 的 serializer 只服务其自身 ID/内部比较）。测试以独立 golden oracle（硬编码字节字面）验证该实现与附录 C 逐项一致。
- ⚙-8 **基线修正案 A4 提案**（r2-B3 裁定 glob 必然枚举 queue 目录，构成对 §7 硬禁令的实质修订，不能以计划级解释放行）：
  - **提案文本**（r3ext-B1 收紧，r6-m3 精化）：基线 §7 增补限定例外——"Phase 5 持久化层的 preflight 阶段，为执行 §9 强制的 `.tmp.*` 清理，允许枚举 `review_queue/` 目录。**枚举所得名称仅可用于两个操作：`.tmp.*` 前缀匹配判定，及匹配后的直接 unlink**；不得解析名称中的 ID、与预期 rq ID 比较、记录、返回或据此进行业务分支。对不匹配条目不得 stat/read/据其存在性分支业务逻辑。（temp 名内嵌 target basename，构成潜在 queue 信息通道，本例外不授予读取该信息的权利。）§7 其余禁令（不读 decision、不按 queue/decision 状态分支）不变。"

## 3. Contract（忠实转写）

### 3.1 Queue request artifact（基线 §6）

- Schema 全 12 键：`schema_version=1`、`template_version=1`、`review_queue_item_id`、`source_eligibility_id`、`source_evaluation_id`、`source_snapshot_digest`、`experiment{task_id, without_memory_run_id, with_memory_run_id}`、`status="pending"`（恒定）、`summary`、`evidence_summary{validation_verdict, pack_utility_delta, verified, unknown, contradicted}`、`missing_information`、`decision_options`。
- 字段来源全冻结（同一 rq ID 只对应一种合法字节）：
  - `evidence_summary.*` ← reflection.outcome_snapshot 对应字段逐一 copy；
  - `experiment` ← snapshot 三字段 copy-only；
  - `missing_information` ← reflection.missing_information 原对象数组逐字节 copy（顺序同 reflection）；
  - `decision_options` 恒 `["accept","reject","defer","revise"]`（顺序冻结）；
  - `summary` = 附录 A SUMMARY 模板渲染：`experiment {task_id}: runs {without_run_id} -> {with_run_id}, verdict {verdict}.`（插值按附录 C token 规则）；**加载时必须重渲染并整体比较，不从自由文本反解析事实**。
- **锚点等式全集**（producer 内强制 + 落盘 preflight 复验；r1-9）：
  1. `rq.source_eligibility_id == eligibility.eligibility_id`；
  2. `eligibility.source_reflection_id == reflection.reflection_id`；
  3. `rq.source_evaluation_id == reflection.source_evaluation_id`（及 §4.2 硬等式经 reflection 传导至 enriched）；
  4. `rq.source_snapshot_digest == reflection.source_snapshot_digest`。
- **gate:upstream 型字节比较**（r2-B4 更名；S5.3 对给定 artifact 的 canonical 比较即此型）：producer 以冻结 `build_eligibility(reflection, enriched)` 重建 eligibility 并 canonical 字节比较——eligibility 必须是冻结 producer 对该 (reflection, enriched) 的唯一合法产物；source 再准入由冻结链内部（build_eligibility → build_reflection）天然覆盖；ineligible → fail-closed。调用纯函数、无 I/O、无环（queue_request → eligibility → reflection_builder 单向）。
- locator：`source_evaluation_id + source_snapshot_digest` 直接可计算 `evaluations/{eval}/{digest}/` 目录；写入前校验 locator 与 eligibility/reflection 锚点一致。
- 仅 eligible 生成；每个 `source_eligibility_id` 至多一个请求。

### 3.2 identity（基线 §8）

- `rq_` payload **仅 `{source_eligibility_id}`**（不含版本号——修复 R2-4 重复 pending）：schema/template 升级不改 rq ID；重放遇文件内版本不同 → fail-closed 交人工迁移，绝不生成第二个 pending。
- ID 语法正则强制（`^rq_[0-9a-f]{64}$` 等五族，小写 hex）；总路径超限 → fail-closed。

### 3.3 目录与文件布局（基线 §9）

```
state_dir/
  evaluations/{evaluation_id}/{source_snapshot_digest}/
    enriched_utility_evaluation.json
    reflection.json
    eligibility.json
  review_queue/
    {review_queue_item_id}.json
```

### 3.4 文件系统与隔离前置条件（基线 §9）

- state_dir 必须本地、支持 POSIX link/fsync，且不在 iCloud/File Provider 同步根下；能力不满足 → 启动即 fail-closed（实现见 ⚙-5）。
- **隔离前置条件**（r1-12 补转写）：一个 state_dir = 一个隔离域，workspace/scope 隔离由调用方保证（G-5 接受为接口前置条件）。
- **单写者前置条件**：见 ⚙-6。

### 3.5 类型化 preflight（基线 §9）

- eligible 链合法集：`{∅, [E], [E,R], [E,R,El], [E,R,El,Q]}`（[E,R,El] 为 crash 前缀可补 Q）；
- ineligible 链合法集：`{∅, [E], [E,R], [E,R,El]}`（[E,R,El] 为终态；`ineligible ∧ Q 存在` = corruption → fail-closed，Q 路径按 ⚙-4 纯哈希计算）；
- 任何非前缀组合（有下游缺上游）→ 零写入报错，不反向愈合；
- 既有正式文件一律**重建预期对象做字节比较**（含版本、内部 ID、文件名、目录 digest 段）；相等 → 幂等继续，不等 → 报错且**不触碰既有文件**；
- **E 的字节级检查（r2-B5）**：E 为根证据不可从上游重建，其磁盘检查 = ① canonical 字节自检：`raw bytes == canonical(parse(raw bytes))`（非 canonical 空白/键序/重复键必然检出）② §4.2.1 全套再准入 ③ digest 复算 == 目录段 ④ **路径绑定等式**：`E.source_evaluation_id == E.source_evaluation_snapshot.evaluation_id == 所在 evaluations/{} 段`（r2-B2；字段名依契约 06，r3ext-D1）；
- preflight 遇 `.tmp.*` 一律先 unlink 清理再评估链状态（授权域见 ⚙-8/修正案 A4）；
- **空目录骨架的类型化等价（r6-m1）**：`evaluations/{eval}/{digest}/` 等真实目录骨架**不构成正式 artifact 状态**——只要其中不存在意外正式目标或非允许条目，空目录骨架在 typed state 中等价于对应文件均缺失（如空 digest 目录 ≡ ∅ 态）；出现非允许条目 → corruption fail-closed；
- **写操作豁免精确定义**（r1-11）：preflight 全程唯一允许的变更 = 匹配 `.tmp.*` 的 unlink；mkdir/open-for-write/link/truncate/replace 一律违规（由 I/O shim audit 强制）。

### 3.6 发布序列（no-replace；基线 §9）

单文件序列（r6-m2 精化，shim 操作级）：①a `open_exclusive(temp)`（O_CREAT|O_EXCL，`.tmp.<target-basename>.<nonce>` 同目录）→ ①b `write_all`（短写循环补齐或失败，**单次 write() 返回成功不视为写完**）→ ② `fsync_file(temp fd)` → ①c `close` → ①d **temp 读回与预期字节整体比较**（readback，不符 → readback gate 报错）→ ③ `link(temp, target)`（create-if-absent，目标已存在则失败）→ ④ `unlink(temp)` → ⑤ `fsync_dir(所在目录)`。目录创建：`mkdir` 后 `fsync(父目录)`，自根向叶。**禁止 `os.replace` 触碰任何既有目标**。link 失败于"已存在" → 幂等字节比较：**只读比较**，相等继续、不等报错，既有 target 在任何路径下字节不变（r1-10）。

**链级顺序（r1-8、r2-C1 修订）**：E、R、El 各自完整走完五步（含 ⑤ 目录 fsync）之后，才允许出现任何 `review_queue/` 的**发布类操作**（mkdir-for-publish、temp 创建、写、link）。preflight 阶段对 `review_queue/` 内 `.tmp.*` 残留的清理 unlink **不属发布类操作**（白名单内、不产生任何可见 target），可先于 E/R/El 执行且不破坏可见性不变量。queue request 最后写：Q target 落盘前链路对人不可见。

### 3.7 崩溃保证（基线 §9）

任一崩溃点磁盘状态 ∈（合法前缀集 ∪ `.tmp.*` 残留 ∪ ③④ 之间 target+temp 并存），三者均被 preflight 归一（清 temp → 前缀评估 → 从缺失第一环重放）。恢复入口按 ⚙-4 收敛矩阵划分：E durable 后 → `resume_learning_chain`（state 根寻址，不依赖调用方仍持有原 enriched 对象；r1-3）；E durable 前（∅/仅-temp）→ 调用方持 enriched 重新 `persist_learning_chain`（r2-B1）。超出 fsync 语义的破坏由字节校验兜底 → fail-closed。

### 3.8 E5 关闭条件（r1-2、r2-B5 修正，三分量）

1. **目录段等式（链级一次）**：`重算 digest(E.source_evaluation_snapshot) == 所在目录 digest 段 == reflection.source_snapshot_digest`——即 §4.2 硬等式 2 的目录段分量；E、El 本体无 digest 字段、Q 不在 digest 目录，不适用"文件自带 digest==目录段"的字面。
2. **逐字节重建比较（派生件 R/El/Q）**：落盘后从磁盘 E 出发以冻结 producer 链重建预期对象，canonical 序列化与磁盘字节逐字节相等。
3. **E canonical 字节自检**：E 不可从上游重建，但其磁盘字节必须满足 `raw bytes == canonical(parse(raw bytes))` + §3.5 的再准入/digest/路径绑定全套——附录 C"既有文件比较 = 字节相等"对 E 同样成立，磁盘恢复路径（resume）与内存路径（persist）等强。

## 6. 风险与注记

- **fsync 语义在单元测试不可直接验证**：测试锁定调用序列（shim audit）与重放收敛性，非磁盘物理保证——与基线"超出 fsync 语义的破坏由字节校验兜底"口径一致。
- **link 语义跨文件系统差异**：由 RED-2 全序列 probe 前置挡住，设计内 fail-closed。
- **并发**：单写者为接口前置条件（⚙-6）；违反前置条件下的行为不做承诺，但任何可观测异常均 fail-closed 不静默、resume 可收敛。
- **E 的根证据地位**：重放时 E 缺失而下游存在 = 非前缀 → 报错，不得用内存态 enriched 补写 E 后继续；补写仅允许从缺失的第一环开始且其上游全部通过字节比较。
- **⚙-8 已按 r2 红队裁定升级为基线修正案 A4**（§9 temp 清理义务与 §7 枚举禁令正面冲突，无实现层回避路径）；批准依赖见 §5 流程第 1 条。
- **pre-E 崩溃态的恢复责任在调用方**（⚙-4 收敛矩阵）：∅/仅-temp = 链未持久开始，非缺陷而是 E 根证据地位（§3）的直接推论；resume 对此 fail-closed 是设计内行为。
- Codex 配额：单次重审查可耗 20+ 分钟额度；轮次间配额耗尽时由 Claude 增量自核留证、事后补外部复核。
